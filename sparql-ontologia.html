Query SPARQL 2

Query sulla nostra ontologia

Query che verificano direttamente la nostra estensione custom: la classe bo:CasaDiQuartiere e le sue istanze. Sono indipendenti dal vocabolario OntoPiA sottostante, già verificato nella pagina precedente.

Keyword SPARQL utilizzate in questa pagina:

OPTIONAL BIND DISTINCT ORDER BY UNION FILTER REGEX LIMIT

La query è stata scritta ed eseguita direttamente in Protégé, tramite il pannello SPARQL Query integrato, sul grafo completo del progetto: lo schema più le 32 istanze generate dagli LLM (si veda la pagina LLM), scaricabile qui sotto. Le query sul vocabolario OntoPiA riusato (COV, CLV, AccessCondition) sono nella pagina SPARQL 1 · OntoPiA.

Il grafo su cui girano le query di questa pagina è disponibile per il download: case_di_quartiere_kg.ttl.

Query 1 — Completezza strutturale delle 32 Case

Obiettivo: verificare che ogni istanza di bo:CasaDiQuartiere abbia gestore, indirizzo, orari e sito web, individuando eventuali lacune nella nostra classe.

PREFIX bo: <https://example.org/casediquartierebologna#>
PREFIX poi: <https://w3id.org/italia/onto/POI/>
PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX sm: <https://w3id.org/italia/onto/SM/>
PREFIX ac: <https://w3id.org/italia/onto/AccessCondition/>

SELECT DISTINCT ?nome ?haGestore ?haIndirizzo ?haOrari ?haSitoWeb
WHERE {
  ?casa a bo:CasaDiQuartiere ;
        poi:POIofficialName ?nome .
  OPTIONAL { ?casa bo:isManagedBy ?g . BIND(true AS ?haGestore) }
  OPTIONAL { ?casa clv:hasAddress ?a . BIND(true AS ?haIndirizzo) }
  OPTIONAL { ?casa ac:hasAccessCondition ?o . BIND(true AS ?haOrari) }
  OPTIONAL { ?casa sm:hasWebSite ?w . BIND(true AS ?haSitoWeb) }
}
ORDER BY ?nome

Risultato: 32 righe, una per Casa, senza duplicati. Indirizzo e sito web presenti su tutte e 32. Gestore assente solo per Stella e Tolmino. Orari assenti solo per Foscherara, Pilastro e Villa Mazzacorati.

Interpretazione: le lacune corrispondono esattamente alle celle vuote nel CSV originale per quelle stesse Case: il grafo riflette correttamente l'assenza del dato invece di inventarlo. Il pattern con OPTIONAL + BIND(true AS ...), invece di selezionare direttamente il valore, evita le righe duplicate quando una proprietà è multi-valore (vedi Sfide).

Query 2 — Case ospitate in un edificio storico e relativo gestore

Obiettivo: verificare quali istanze di bo:CasaDiQuartiere hanno un valore per bo:isLocatedInHeritageBuilding, e chi le gestisce, incrociando la proprietà ponte custom con quella riusata da COV.

PREFIX bo:  <https://example.org/casediquartierebologna#>
PREFIX poi: <https://w3id.org/italia/onto/POI/>
PREFIX cov: <https://w3id.org/italia/onto/COV/>

SELECT ?nome ?edificio ?gestore
WHERE {
  ?casa a bo:CasaDiQuartiere ;
        poi:POIofficialName ?nome ;
        bo:isLocatedInHeritageBuilding ?edificio ;
        bo:isManagedBy ?g .
  ?g cov:legalName ?gestore .
}
ORDER BY ?nome
LIMIT 10

Risultato: esattamente 2 righe, ben al di sotto del LIMIT 10: Villa Bernaroli, gestita da "Centro Sociale e Orti Villa Bernaroli APS", e Villa Mazzacorati, gestita da "Associazione Centro Sociale Villa Mazzacorati".

Interpretazione: il risultato coincide esattamente con quanto emerso nell'esplorazione su ArCo (si veda SPARQL 1 · OntoPiA): solo queste due Case hanno un edificio storico catalogato ufficialmente, e la query conferma che il collegamento tra bo:isLocatedInHeritageBuilding e bo:isManagedBy è stato popolato correttamente per entrambe.

Query 3 — Case aperte di sabato o domenica

Obiettivo: individuare le Case aperte nel fine settimana, combinando con UNION la condizione sul sabato e quella sulla domenica.

PREFIX bo:  <https://example.org/casediquartierebologna#>
PREFIX poi: <https://w3id.org/italia/onto/POI/>
PREFIX ac:  <https://w3id.org/italia/onto/AccessCondition/>
PREFIX ti:  <https://w3id.org/italia/onto/TI/>

SELECT DISTINCT ?nome
WHERE {
  ?casa a bo:CasaDiQuartiere ;
        poi:POIofficialName ?nome .
  {
    ?casa ac:hasAccessCondition ?o1 .
    ?o1 ac:hasDayOfWeek ti:Saturday .
  }
  UNION
  {
    ?casa ac:hasAccessCondition ?o2 .
    ?o2 ac:hasDayOfWeek ti:Sunday .
  }
}
ORDER BY ?nome

Risultato: 22 Case su 32: Area Ortiva Paleotto, Casa Gialla, Casa del Gufo, Croce Coperta, Della Pace, Due Agosto 1980, Fondo Comini, Il Parco, Italicus, Katia Bertasi, La Dacia, Lunetta Gamberini, Montanari, Nello Frassinetti, Pescarola, Rosa Marchi, San Rafel, Santa Viola, Scipione dal Ferro, Stella, Tolmino, Villa Torchi.

Interpretazione: più di due terzi delle Case restano aperte almeno un giorno del weekend; il DISTINCT evita che una Casa compaia due volte se risulta aperta sia sabato sia domenica, dato che i due rami dell'UNION possono soddisfare lo stesso ?casa contemporaneamente.

Query 4 — Case che aprono prima delle 9 di mattina

Obiettivo: filtrare le fasce orarie di apertura in base a un valore temporale, per individuare le Case con l'orario di apertura più anticipato.

PREFIX bo:  <https://example.org/casediquartierebologna#>
PREFIX poi: <https://w3id.org/italia/onto/POI/>
PREFIX ac:  <https://w3id.org/italia/onto/AccessCondition/>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>

SELECT DISTINCT ?nome ?apertura
WHERE {
  ?casa a bo:CasaDiQuartiere ;
        poi:POIofficialName ?nome ;
        ac:hasAccessCondition ?o .
  ?o ac:opens ?apertura .
  FILTER (?apertura < "09:00:00"^^xsd:time)
}
ORDER BY ?apertura

Risultato: 9 Case: Katia Bertasi (07:00), poi otto Case alle 08:00 (Santa Viola, Nello Frassinetti, Villa Torchi, Scipione dal Ferro, Croce Coperta, Giorgio Costa, Croce del Biacco) e Montanari alle 08:45.

Interpretazione: la stragrande maggioranza delle Case apre dalle 9 in poi; Katia Bertasi, con apertura alle 7:00, è la Casa più mattiniera dell'intero dataset.

Query 5 — Case con "giardino" nel nome

Obiettivo: cercare, con REGEX case-insensitive, le Case il cui nome ufficiale contenga la parola "giardino".

PREFIX bo:  <https://example.org/casediquartierebologna#>
PREFIX poi: <https://w3id.org/italia/onto/POI/>

SELECT ?nome
WHERE {
  ?casa a bo:CasaDiQuartiere ;
        poi:POIofficialName ?nome .
  FILTER (REGEX(?nome, "giardino", "i"))
}
ORDER BY ?nome

Risultato: nessuna riga.

Interpretazione: nessuna delle 32 Case ha "giardino" nel proprio nome ufficiale, anche se diverse sono fisicamente ospitate dentro o accanto a un parco o giardino pubblico: quel legame andrebbe cercato in un'altra proprietà, non nel nome, e resta infatti fuori dallo scopo di questa classe (si veda l'approfondimento sulle categorie POI in SPARQL 1 · OntoPiA).
