Query SPARQL 2

Query sulla nostra ontologia

Query che verificano direttamente la nostra estensione custom — la classe bo:CasaDiQuartiere e le sue istanze — indipendentemente dal vocabolario OntoPiA sottostante.

Keyword SPARQL utilizzate in questa query:

OPTIONAL BIND DISTINCT ORDER BY

Le query sul vocabolario OntoPiA riusato (COV, CLV, AccessCondition) sono nella pagina SPARQL 1 · OntoPiA.

Query 1 — Completezza strutturale delle 32 Case

Obiettivo: verificare che ogni istanza di bo:CasaDiQuartiere abbia gestore, indirizzo, orari e sito web, individuando eventuali lacune nella nostra classe.

PREFIX bo: <https://example.org/casediquartierebologna#>
PREFIX poi: <https://w3id.org/italia/onto/POI/>
PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX sm: <https://w3id.org/italia/onto/SM/>
PREFIX ac: <https://w3id.org/italia/onto/AccessCondition/>

SELECT DISTINCT ?nome ?haGestore ?haIndirizzo ?haOrari ?haSitoWeb
WHERE {
  ?casa a bo:CasaDiQuartiere ;
        poi:POIofficialName ?nome .
  OPTIONAL { ?casa bo:isManagedBy ?g . BIND(true AS ?haGestore) }
  OPTIONAL { ?casa clv:hasAddress ?a . BIND(true AS ?haIndirizzo) }
  OPTIONAL { ?casa ac:hasAccessCondition ?o . BIND(true AS ?haOrari) }
  OPTIONAL { ?casa sm:hasWebSite ?w . BIND(true AS ?haSitoWeb) }
}
ORDER BY ?nome

Risultato: 32 righe, una per Casa, senza duplicati. Indirizzo e sito web presenti su tutte e 32. Gestore assente solo per Stella e Tolmino. Orari assenti solo per Foscherara, Pilastro e Villa Mazzacorati.

Interpretazione: le lacune corrispondono esattamente alle celle vuote nel CSV originale per quelle stesse Case — il grafo riflette correttamente l'assenza del dato invece di inventarlo. Il pattern con OPTIONAL + BIND(true AS ...), invece di selezionare direttamente il valore, evita le righe duplicate quando una proprietà è multi-valore (vedi Sfide).

Aggiungere qui eventuali ulteriori query specifiche sulla classe bo:CasaDiQuartiere (es. verifica di bo:isLocatedInHeritageBuilding sulle case ospitate in edifici storici).
